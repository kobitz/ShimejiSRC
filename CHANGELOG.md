# Changelog

Per-version release history for the Shimeji AI fork. The runnable app ships as a GitHub Release asset (`Shimeji-Install-Windows.zip`) at **github.com/kobitz/ShimejiSRC**; the README is intentionally version-agnostic, so this file + the GitHub release notes are the changelog of record. Release *mechanics* (how to cut one) live in `CLAUDE.md` → Distribution / Releases.

## Next

- Mascots on a browser video's edges follow scrolling smoothly: the extension reports per frame and Shimeji eases the video rect. Reinstall `shimeji-video-tracker.xpi` (v1.8).
- Video controls: "pause/play this video" (media key) and "full screen this video" (browser extension; YouTube, Twitch, Netflix); volume up/down/to N% unchanged. Reinstall the updated `shimeji-video-tracker.xpi` and add `netflix.com` to `VideoAreaAllowedHosts`.
- **Window errands phase 2: snap / center.** "Snap this to the left" (also right, top, bottom, center) is now done with the mascot's body: it grabs the window's nearest bottom corner, walks it to the matching corner of the target area and throws it into place (quick ease-out tween). Maximized windows are windowed first; same Window Interaction permission and `AgentVisualMoves` switch as phase 1.
- **The project is now called koaibo** (was the working title ShimejiSRC): About tab, installer (`installer\koaibo.iss`, `koaibo-Setup-<ver>.exe`, default folder `koaibo`), portable build folder `dist\koaibo`, README/CREDITS, the Get Mascots user-agent and default catalog URL (`github.com/kobitz/koaibo`), calendar-export IDs. The installer AppId is unchanged, so an existing install upgrades in place. `Shimeji.exe` / `Shimeji-ee.jar` keep their names for now. Credits (Shimeji-ee / Kilkakon and the rest) are unchanged.
- **Voice: time to finish the command.** Saying just the name ("hey Hornet") or trailing off ("Hornet, can you...") no longer gets an instant reply: the call is held for `VoiceNameGraceMs` (default 4000, 0 = off) and joined with the next thing you say; if nothing follows, the mascot answers the name alone. One-word commands ("Hornet sit") and sentences that end normally stay instant.
- **Renamed Mascot Shop to Get Mascots** (tray button + window title). Removed two stray zips from `img/`.
- **Physical window errands (phase 1):** asking a mascot to maximize / restore / minimize a window, or to send it to another screen, is now done with its body instead of instantly. It jumps at the title-bar button (the mascot's own `Jumping` action, so any set works) and the window changes when it arrives; for a move it walks to the window's nearest bottom corner (jumping to it if it is off the floor), holds it at its feet, walks it across, sets it down, and maximizes it afterwards if it was maximized. A maximized window is first windowed by jumping at the maximize/restore button, then grabbed. If the user drags, maximizes or minimizes the window mid-carry the mascot lets go ("taken"). Minimized windows are restored directly (no taskbar to jump at). The menu item "Throwing Windows" is now **Window Interaction** (same `Throwing*` keys): a set with it off falls back to the old instant behaviour. `AgentVisualMoves=false` also turns the visible version off. Pure planner `WindowErrandPlan` + director `WindowErrand` (fake-stage tests in `WindowErrandTest`); caption button positions are the stock Windows 10/11 metrics (`CaptionButtons`) and need on-hardware tuning.
- **Settings/debug polish:** Settings window default height trimmed to fit the General tab (Chat Bubbles already scrolls); About tab now reads ShimejiSRC 2.0, developed by kobitz and Claude, based on Shimeji-ee 1.0.23 by Kilkakon (GitHub + Shimeji-ee links replace Kilkakon's Discord/Patreon buttons); Reveal Statistics window puts the Behaviours/Variables tabs to the right of the readouts, and the Variables tab now also lists per-mascot `userData` (e.g. `dashStamp`) so it is no longer always empty.
- **Docs:** README/CLAUDE.md now state the design principle explicitly: once installed the app runs fully offline; weather, the Mascot Shop and the cloud AI provider are optional network extras.
- **Optional cloud / OpenAI-compatible AI provider** (contributed by 26th-Official) - Settings -> Chat Bubbles -> *AI Provider* lets the assistant use any OpenAI-compatible API (OpenAI, OpenRouter, Groq, Together) or a local OpenAI-style server (LM Studio, llama.cpp, vLLM) instead of Ollama. Local Ollama stays the default. The key lives in `conf/api.properties` (gitignored) or `SHIMEJI_AI_API_KEY`. Turning API mode on shows a one-time notice of what gets sent. Semantic drive search stays off in API mode unless `DriveSemanticRemote=true`, cached embeddings are tagged by model so switching providers rebuilds them, and `max_completion_tokens` is used for api.openai.com.

## v2.0 (Nov 2026)

The agent release: the mascot can act on your computer (opt-in), plus the Mascot Shop and a one-file installer.

- **Click away closes the right-click menu again** - the global mouse hook that does this was only registered when hotkey bindings existed, so a fresh install (no bindings) never dismissed the menu. The hook is now always registered.
- **Hide a mascot from the menus** - put an empty file named `hidden.txt` in a mascot's `conf` folder (`img\<Name>\conf\hidden.txt`) and it no longer appears in *Choose Shimeji* or gets picked by *Call Shimeji* / a tray click. It still loads and can be spawned by other mascots' behaviors, and a hidden set that is already running stays running when you change your selection. Meant for sidekick sets such as Hornet's Needle.
- **Cleaner installer bundle** - the installer is now built from the repo's own `conf\` and `img\` (default settings from `conf\settings.properties`), not from your personal install folder; stray files in `img\` are no longer swept up, and the setup wizard always shows the install-folder page.
- **Safe installer testing** - `installer\build-installer.bat 2.0 test` builds `dist\ShimejiSRC-Setup-2.0-TEST.exe`, a throwaway installer with its own app id, its own shortcuts and a default folder of `dist\test-install`, so trying it never touches (or replaces the uninstall entry of) your real or working install. A normal installer remembers where the same app was installed before and offers that folder again, which is how a test run can land on top of a working folder.
- **Smaller installer: Java is downloaded, not bundled** - `ShimejiSRC-Setup-<ver>.exe` no longer carries the ~150 MB `jre\` folder. At the end of the install it downloads a pinned Temurin 21 JRE (exact URL and SHA-256 are looked up from the Adoptium API when the installer is built, and Setup refuses a file that doesn't match), unpacks it to `<install>\jre` and shows progress in the wizard. Skipped if `jre\` already exists (upgrades). If the download fails (offline) Setup says so and carries on: the app then uses any Java 17+ on the machine. The uninstaller removes `jre\`. `installer\build-installer.ps1 -BundleJre` builds the old fully-offline installer. **Written without Windows/Inno Setup access: not compiled or run yet.**
- **Stacked chat bubbles: higher tails point steeper down** - the bubble nearest the mascot looks exactly as before; each bubble stacked above it leans its tail less (points more downward toward the mascot), easing from 1x to about 0.4x the further up it sits. The tip still lands on the mascot.
- **Voice: commands no longer cut off mid-sentence** - three causes fixed. (1) While anything was playing through the speakers the command window was capped at 3 s, which ends "hey holo, can you turn..." right there; it is now 7 s (12 s with quiet speakers, was 8). (2) A dip to 70% of the loudest syllable counted as silence, so a loud name followed by quieter words started the end-of-speech clock immediately; now it must drop below 40% of the peak AND sit near the noise floor. (3) The start of a phrase is no longer clipped: each recording now begins with the 0.6 s of audio from just before speech was detected. Default end-of-speech quiet raised from 1.2 s to 1.5 s (`VoiceSilenceHoldMs`, live). Trade-off: replies start about 0.3 s later.
- **Build.bat works on any machine** - new option [4] *Portable build*: runs Ant, finds Launch4j (your `LAUNCH4J`, `tools\launch4j`, or Program Files; offers to download it if missing), generates its config on the fly and produces `dist\ShimejiSRC\Shimeji.exe` with `conf\`, `img\` etc. beside it (bundled `jre\` if present, otherwise any installed Java 17+). Clear messages if Ant or the JDK is missing. Options [1]/[2] and `Build.local.bat` work exactly as before (and stay the default when `Build.local.bat` defines your Launch4j paths). **Untested on Windows at authoring time.** New `CREDITS.md`.
- **Agent: volume and media controls** - "turn down the volume" (a bit / a lot), "turn it up", "make it quieter", "set the volume to 30%", "mute", "pause the music", "skip this song", "go back a song". Sent as the same media keys a keyboard has, so they work with Spotify, browsers, anything. Setting an exact percent drops to zero first and steps up (the real level can't be read), mute is a toggle. Requests to shut down, restart, sleep, log off, close/kill, delete, install or uninstall are refused with "This action is not within my parameters." (the model is told to use the same line, and those verbs only count when aimed at a computer thing, so ordinary chat like "close enough" is untouched).
- **Agent: scheduling** - "play a sound in 20 minutes" / "remind me to stretch at 8:40pm" / "set a timer for 10 minutes" (shows the usual countdown bubble and plays a generated chime when it ends, `TimerSound=false` mutes it); "open youtube.com tomorrow at 9am" (web pages, files by name from your folders, programs by Start Menu name - never exes/scripts, re-checked when it fires); "add a meeting with Sam on Friday at 3pm to my calendar" (writes an `.ics` with a 10-minute alarm, opens it in your calendar app, and the mascot also reminds you); "what's scheduled" / "cancel that" / "cancel all my reminders". Schedules survive restarts (`agent-schedule.tsv`); anything more than 15 minutes late is reported as missed, never run. **Typing into another app later** ("ask claude to continue at 8:40pm") is a second opt-in, `AgentTypeEnabled=true`: at the time the mascot finds the window by title (an ambiguous or missing match does nothing), brings it to the front, checks it really has focus, and pastes the line + Enter. Only the active browser tab is findable (by its window title). Times are parsed from your own words only; the model cannot create schedule or typing actions.
- **Agent: file moves you can watch** — after you confirm, the mascot opens the source and destination folders as Explorer windows side by side (upper part of the screen, floor left clear), walks along the floor to the source, the file visibly flies out of that window onto the mascot (the file really leaves its folder: it is parked in a hidden `.shimeji-hold` folder beside it), carries it across, and drops it into the destination window. If the mascot can't make the trip it just does the move; a destination clash puts the file back; a crash mid-carry is repaired next start (`agent-holding.tsv`). `undo` still works. Set `AgentVisualMoves=false` for instant moves. Tidy-ups of many files stay instant.
- **Voice: longer pause allowed between words** — an utterance now ends after 1.2 s of quiet instead of 0.4 s, so short pauses no longer cut commands off. Tune with `VoiceSilenceHoldMs` (300-3000, live, no restart). Trade-off: replies start ~0.8 s later.
- **Agent: move windows between monitors, move files with a confirm bubble** — "move this to my other monitor" / "send Firefox to the second screen" / "move chrome to monitor 2" (other, next, left, right, primary, second, third) keeps the window's relative spot and size, shrinking only if it would not fit, and restores then re-maximizes a maximized window. "Move report.pdf to Documents" (or "...the budget file to the desktop") moves one loose file between Desktop/Documents/Downloads/Pictures/Videos/Music, your `AgentFolders`, or a folder directly inside them; ambiguity is asked about, nothing is overwritten, and `undo` puts it back. File moves and tidy-ups now ask through a small yes/no chat bubble above the mascot instead of a dialog: it fades out over its last 4 seconds and a bubble that fades away counts as "no" (hovering it pauses the countdown). Monitor rectangles come from Win32, the same coordinates as windows, so carrying/snapping stay correct on scaled displays.
- **One-file Windows installer** — `installer/build-installer.bat` assembles a scrubbed bundle from your install folder (allowlist + a scrub check that aborts if any `memory.json`/logs/chat/journal slipped in) and compiles `dist/ShimejiSRC-Setup-<version>.exe` with Inno Setup 6.3+ (`installer/ShimejiSRC.iss`): per-user install by default (the app writes next to itself), optional desktop/startup shortcuts, Start-menu entries incl. the Admin launcher and AI setup, optional AI setup after install, uninstaller that asks before deleting settings/memories. Which mascots ship is `installer/mascots.txt`; sounds are collected from their XML. Reinstalling never overwrites `settings.properties`.
- **Mascot Shop** — tray menu -> *Mascot Shop...*: browse a curated catalog (`conf/shop_catalog.json`, fetched from `ShopCatalogUrl`, default the repo copy, with the bundled file as offline fallback). Free redistributable mascots install in one click (https only, SHA-256 verified, safe unzip: no path escapes, no program files, size/entry caps, never overwrites an existing mascot). Creator-hosted mascots (Cachomon, DeviantArt, Patreon...) open the creator's page and are brought in with *Import .zip* - the shop never scrapes or re-hosts them. New classes in `shop/`; `ShopTest`.
- **Agent tools (opt-in)** — with `AgentEnabled=true` the mascot can act on request: focus/minimize/maximize/restore/snap another app's window by name, and tidy a folder (default `Downloads`, see `AgentFolders`) into Images/Documents/Archives/Audio/Video/Installers after you confirm a preview, with `undo`. Never deletes or overwrites; every move is journalled in `agent-journal.tsv`. Only your own messages can trigger actions (not on-screen text or overheard audio). Windows only for window control. Commands are read from your own words ("minimize my browser", "snap Notepad to the left", "clean up my Downloads", "undo"), so they work even if the model doesn't emit tags; with the agent off the mascot says how to turn it on and no longer claims abilities it lacks.
- **Fix: hard freeze (deadlock) in chat bubbles** — a bubble being shown from the tick thread could deadlock against the Swing thread repainting it (seen in the StallWatchdog log); the show now happens on the Swing thread. **Carry:** "carry my browser around for a minute" now parses the duration (a minute / a bit / a couple of minutes / N seconds-minutes); the mascot lets go if you drag, maximize or minimize the window yourself, and keeps holding it if you only resize it.
- **Hardening / hygiene (pre-2.1 audit)** — `nvidia-smi` is launched by absolute path (no cwd lookup under Admin.bat); the installer scrub now also removes `api.properties` and `agent-*.tsv`, and strips `AiApiKey` from the shipped default settings; the shipped default `settings.properties` no longer carries dev tuning (`OllamaResourceCap=0.125`, `OllamaKeepAliveSec=3`); agent state files are gitignored; stray `img/Hornet/conf/shimejiSRC fix path.md` removed.
- **Agent: "this window" works** — "minimize/maximize/restore this window" (also "it", "that window", "the current one") now acts on the window you were on; before, the phrase was dropped and the request fell through to the (possibly offline) chat model.
- **Agent commands no longer wait for the model** — "minimize my browser", "snap X left", "undo" etc. run immediately from your words (typed, voice or bubble reply), skip the chat reply, and work with Ollama off, like mascot actions.
- **Agent Tools and Weather toggles** - tray -> Allowed Behaviours now has **Agent Tools** (`AgentEnabled`) and **Weather (online)** (`WeatherEnabled`); both take effect immediately. **Weather is now off by default** (it was the one feature that contacted outside services, including a plain-HTTP IP lookup); tick the box to opt in.
- **Agent: window errands end when the goal is reached** - the errand finishes the moment the maximize/minimize/restore press lands (or the window arrives), instead of re-checking the window after the mascot falls and landing; if you restored or minimized the window in the meantime the mascot no longer jumps up and does it again.
- **Agent: other mascots ride a carried window** - a window being carried used to vanish from every mascot's surface scan, so mascots walking or climbing on it were left behind; now only the carrier ignores it, and the rest follow it as they would a window you drag.
- **Agent: held windows stay glued** — if you pick the mascot up (or it falls / is thrown) while it carries a window, the window rides along; the mascot waits for you to let go, lands, and resumes the walk instead of dropping the window.
- **mascot_patcher: Window Errand Readiness** — new patch that checks each mascot has the Walk / Jumping / Fall actions window errands use, adds the standard Fall when only that is missing, and warns about sets that cannot do errands.
- **Agent: monitor moves are thrown** — "send this to the other screen": the mascot grabs a corner of the window, lifts it and flings it in an arc onto the other monitor.
- **Agent: window help** — "This window" means the one in front when you clicked the mascot. "Move/snap this window left" works as a visible errand. (The instant "carry this window around"/"drop it" commands were removed in favour of physical errands.) "Clean up my drive/computer" now previews a Downloads tidy instead of the mascot suggesting files to delete.
- **Shop: full Cachomon list + thumbnails** — the status line shows "N of M mascots" when a filter is active; the catalog now lists every Safe-rated, downloadable Cachomon mascot (~320; link mode, Patreon exclusives flagged), each with a preview thumbnail loaded lazily (3 at a time), cached on disk in `cache/shop-previews`, disable with `ShopThumbnails=false`. New *More sources...* menu (DeviantArt, itch.io, BOOTH, Cachomon, Patreon), list scrolls to top on search, catalog cap raised to 2000, built-in copy split to stay under Java's 64 KB constant limit.
- **Behavior stats in assistant memory** — per image set, `memory.json` now keeps a `stats` object (lifetime totals plus per-day buckets, pruned to 8 days) for distance walked, time sat, jumps, times picked up and falls, counted automatically (hooks in `Move`, `Jump`/`ScanJump`/`ComplexJump`, `Fall`, `Dragged`, and any behavior whose name starts with a `Sit` word). New `Stat` action (`Counter="..."`, optional `Amount`) bumps a custom counter from XML, e.g. Hornet's "Mosscreeps hunted". Direct replies get one factual line ("Your own life (counted, not guessed) - today / this week / all-time"), non-zero items only. Counting only applies to sets that already have a `memory.json`; saves are throttled to every 30 s and flushed on exit. Needs `Counter`/`Amount` in the install `conf/schema.properties`.
- **Collision respects covering windows** — a mascot that isn't always-on-top (global and per-image-set) and is completely hidden behind another window stops acting as a surface until it is uncovered. Always-on-top mascots keep their collision.
- **Settings window taller** — the tray Settings dialog is 720 px tall (was 640, scaled by menu DPI, capped to the screen) so Done/Cancel are fully visible.
- **Freeze fix (likely)** — the first watchdog dump caught the Manager thread inside `Window.setBounds` (a synchronous native call that holds the AWT tree lock) while the Swing EDT was blocked waiting on that lock; with ~30 mascots a slow AWT toolkit thread turned into multi-second tick stalls. Steady-state frames no longer call `setBounds` (the layered-window update already moves/resizes the window); it is only used when a mascot is first shown.
- **Occlusion check no longer stalls the tick** — the covering-window check looked up each mascot's HWND via JAWT every frame, which needs the AWT lock the Swing EDT holds while repainting a translucent window (4.6 s stall caught by the watchdog). The HWND is now looked up once per window and cached. Watchdog GC figures corrected (they were cumulative).
- **Right-click menu diagnostics** — failures opening the menu are now logged (`[Menu] failed to open...`, with stack) instead of vanishing into the event thread's default handler, a slow event thread is logged (`[Menu] ... waited Nms`), and a stale "open" popup reference no longer blocks a new menu.
- **Deadlock fix (the 30-minute freeze)** — the watchdog dump showed a real ABBA deadlock: the tick thread held the mascot-list lock while entering `UserBehavior.next()`, while the Swing thread (a voice name-trigger running a behavior) held that `UserBehavior`'s monitor and asked for the mascot-list lock. Everything, including the right-click menu, died with the Swing thread. The per-mascot tick/apply loop now runs over a snapshot copy outside the list lock.
- **Second half of the deadlock** — `setBehaviorAll`, `setBehaviorAllSafe` (both) and `cancelHeldActions` (menu/hotkey paths) held the mascot-list lock while calling into behaviors, the reverse of what the tick thread does. They now work from a snapshot (`Manager.mascotsSnapshot()`), so no thread takes a behavior monitor while holding the list lock.
- **Cursor read off the tick** — the next watchdog dump caught the Manager thread in `MouseInfo.getPointerInfo()` (called once per mascot per tick; native AWT, waits on the AWT lock) while the Swing thread was inside a multi-second native `Window.setSize` resizing a chat bubble: a 5.5 s stall. The pointer position is now polled by a `CursorPoller` daemon thread (15 ms) and the tick just reads the cached value.
- **Watchdog samples earlier** — a 5.6 s tick stall was only noticed as it ended, so its dump showed an idle Manager. The watchdog now polls every 200 ms, dumps at 1.5 s (and again at 4 s if still stuck), and lists only the Manager/Swing threads plus running or blocked threads.
- **Work-area lookup off the tick** — the 1.5 s watchdog dump caught the Manager thread inside `SystemParametersInfoW` (called per mascot from `getWorkAreaRect`, along with `MonitorFromPoint`/`GetMonitorInfoW`) for 2.9 s while the Swing thread was inside `UpdateLayeredWindow` repainting a translucent window — the desktop was busy and every user32 call queued behind it. Monitor rects and work areas are now enumerated on the scanner thread once a second (`EnumDisplayMonitors`) and the tick does a pure-Java lookup; the old native path remains as a fallback until the table is first filled.
- **Script compile stalls** — two watchdog dumps (2.1 s and 2.7 s, Mario and Mosscreep) had the tick thread inside Nashorn: once compiling scripts while rebuilding a mascot's action tree (the `Script` constructor compiled each source to check syntax and threw the result away, so every behavior build recompiled everything), once in Nashorn's optimistic-type *recompilation* during `BehaviorBuilder.isEffective`. The constructor now stores the compiled script in the shared per-thread cache, and the engine runs with `--optimistic-types=false` so scripts are never recompiled mid-tick. Verified: arithmetic/overflow results, `load` removal, class filter and `java.awt.Point` allowance unchanged.
- **Freeze diagnostics** — new `StallWatchdog`: if a Manager tick runs, or the Swing event thread stops answering, for 4+ seconds it writes one `[StallWatchdog]` log record with every thread's stack, any deadlock, and GC time. `[TickWatch]` lines now include `gc=` (ms spent in GC during the tick).
- **Stale-schema safety** — the XML schema files are read from the install folder, so an install whose `conf/schema.properties` predates the jar made loading fail (`MissingResourceException ... SplashImages`) or broke `Jump`/`ScanInteract` actions (`Arc`/`Look`). `config/SchemaBundle` now supplies the new keys (`Look`, `Arc`, `SplashImages`) from the jar when the installed file lacks them; any other missing key still errors. Copying the new `conf/schema*.properties` into the install folder is still the right thing to do.
- **Kilkakon 1.0.23 parity** — ported the 1.0.23 features we were missing (we were on 1.0.22): new actions **`BringToFront`**, **`MinimizeIE`** (needs Throwing enabled), **`BreedFall`** and **`JumpWithIE`**; **`Arc`** attribute on `Jump`/`ScanJump`/`ComplexJump` (`false` = straight line); **`Look`** attribute on `ScanInteract` (`false` = don't turn toward the target); **multipage splash screens** (`<SplashImages><SplashImage>..` in info.xml, prev/next buttons in the Information window); **Reveal Statistics** now has *Behaviours* (history, newest first, capped at 200) and *Variables* tabs in place of the single Behaviour line; the out-of-memory dialog now resets `Scaling` to 1.0 and shows the heap available to Shimeji (both handlers merged into `Main.showMemoryError`); toggleable behaviours marked `Hidden` now appear in Personal Behaviours; selecting an image set whose child sets link back to it no longer loops forever. Already covered by existing features: per-Shimeji overrides of global toggles (our Universal Behaviours submenu + `*.mascotN` keys). **Not ported:** 1.0.23's under-the-hood image-storage rewrite (our image pipeline is heavily customised). Also `schema.properties` gains `Look`, `Arc`, `SplashImages`.
- **Animated thinking indicator** — the chat bubble's "Thinking..." text is replaced by dots that cycle `.` -> `..` -> `...` (400 ms per step), anchored so they don't jitter as the count changes.
- **Mascot Collision (universal behavior)** — new toggle: while on for a mascot's image set, other mascots treat it like a window (land/stand on it, climb it, etc.). The collision box is the smallest rectangle around the sprite's non-transparent pixels (alpha >= ~10%), so a 128x128 question block with a solid 64x64 middle collides as just that square. Right-click -> Universal Behaviours -> **Mascot Collision** (per image set, `Collision.imageset.<name>`) and tray -> Allowed Behaviours -> **Mascot Collision** (all; clears per-set overrides; `Collision`). Off by default. Windows only. Boxes are published each tick (`environment/CollisionRegistry`), so mascots standing on a moving one ride it.
- **Script sandbox: `java.awt.Point` allowed** — mascot scripts that build a `java.awt.Point` were being blocked by the tightened class filter; that inert value class is now allowed by default (everything else is still blocked unless listed in `ScriptAllowedClasses`).
- **Build cleanup** — removed the unused 25 MB `vosk` jar (it was being merged into the fat jar); `build.xml` now defaults to `jar`, drops the broken upstream `zip`/`zip_package` targets, declares UTF-8, and is versioned 1.9; `MANIFEST.MF` Class-Path case fixed (`jnativehook-2.2.2.jar`) and newline-terminated; `Build.bat` reads machine-specific paths from a gitignored `Build.local.bat`; `.gitattributes` keeps `*.bat` CRLF.
- **VideoAreaServer hardening** — web origins are now allowlisted (`VideoAreaAllowedHosts`, default `youtube.com,twitch.tv`; extension origins and Origin-less local requests still work) instead of `Access-Control-Allow-Origin: *`; request bodies capped at 2 KB; registered ids capped (64 entries / 64 chars). **If you extend the browser extension to more sites, add them to `VideoAreaAllowedHosts`.**
- **TempSensor.exe launched by absolute path** — `CpuTempMonitor` and `FanController` resolve it next to the jar/exe (new `InstallFiles`) instead of by bare name, closing an exe-planting path under the elevated `Admin.bat`.
- **Weather privacy** — new `WeatherEnabled` setting (default true; `false` = no outside lookups at all). README no longer claims "no cloud APIs": it now states that weather questions contact open-meteo (+ `ip-api.com`/`ipapi.co` for `WeatherLocation=auto`) and how to avoid it.
- **Mascot-script sandbox tightened** — mascot XML scripts can no longer name any Java class (`ScriptFilter` used to expose all of `com.group_finity.mascot.*`, which let a script from an untrusted mascot pack rewrite settings like `OllamaEndpoint` or reach `FanController`/`WhisperProcess`), and Nashorn's `load`/`loadWithNewGlobal`/`exit`/`quit` built-ins are removed (they could read files/URLs and kill the app). New `ScriptAllowedClasses` setting (exact class names) for a trusted script that really needs one; blocked attempts log a `[Script] … blocked` warning naming the class. **If a custom mascot stops behaving after updating, check ShimejieeLog for that warning.**

- **`Mascot.java` split, step 1** — 16 pure static text helpers (reply cleanup, timer/action-tag parsing, persona pronoun rewrite, query classifiers) moved to `assistant/ReplyText`; `Mascot.java` 5085 -> ~4700 lines. No behavior change (old vs new outputs byte-identical over ~30k test inputs).
- **`Mascot.java` split, step 2** — the ~700-line right-click menu (`showPopup`) and its two menu-item classes moved to `MascotPopupMenu`; `Mascot.java` ~4700 -> ~4000 lines. Pure move: the extracted method text is identical to the original apart from `Mascot.this`/field/method references now going through the mascot instance.
- **Fullscreen video: mascots no longer hop onto the taskbar** — the fullscreen-monitor set was published and then modified by the scanner thread (browser-reported fullscreen merged in afterwards), so the tick thread could briefly see the monitor as not fullscreen and the floor jumped to the taskbar. It is now built completely, published once as an immutable set, and held 1.5 s after the last sighting to absorb one-scan blips.
- **Chat bubble offset** — bubbles are now placed relative to the mascot's anchor (stable across frames) instead of the center of its current sprite rectangle, so they no longer shift when an action changes the sprite width.
